Overview

In this assignment I implemented Bezier curve and surface evaluation with the de Casteljau algorithm, then worked directly with a half-edge mesh data structure to implement area-weighted vertex normals, edge flips, edge splits, and Loop subdivision. The interesting through-line is that a small, local "contract" of pointers is enough to keep a whole triangle mesh consistent; if you set every half-edge's next, twin, vertex, edge, and face pointers correctly after a local operation, the mesh stays manifold and everything downstream just works.

Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

A degree-n Bezier curve is defined by n control points. De Casteljau's algorithm evaluates the curve at a parameter t by repeatedly linearly interpolating adjacent control points: p'_i = (1 - t) p_i + t p_{i+1}. Each pass produces one fewer point; after n passes a single point remains, and that point lies on the curve. My BezierCurve::evaluateStep performs exactly one pass, which the GUI uses to step through the levels and draw the intermediate control points.

Part 2: Bezier surfaces with separable 1D de Casteljau

A Bezier surface extends the same idea to a 2D grid. I first evaluate every row of control points as a 1D Bezier curve at parameter u, producing one point per row. Those resulting points form a column, which I then evaluate again as a 1D Bezier curve at parameter v. This separable application of the 1D algorithm is what BezierPatch::evaluate implements, reusing evaluate1D and evaluateStep.

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

A shading normal at a vertex is computed by walking around the vertex with the half-edge structure. For every incident, non-boundary triangle I compute the cross product of two edges, cross(p1 - p0, p2 - p0), which points along the face normal and has magnitude equal to twice the face area. Summing these area-weighted normals and normalizing gives the final vertex normal, which produces smooth Phong shading when the mesh is rendered.

Part 4: Edge flip

An edge flip rotates a shared edge between two triangles. The key observation is that no elements need to be created or destroyed; only pointers are reassigned. I named the six half-edges around the two triangles and the four vertices, then rewired the two faces to be (a,d,c) and (a,b,d) instead of the original (b,c,a) and (c,b,d). I also updated the vertex, edge, and face halfedge() pointers so every element still has a valid entry point. Boundary edges are left untouched.

Part 5: Edge split

An edge split inserts a midpoint vertex on the chosen edge and connects it to the two opposite vertices, turning two triangles into four. This operation creates one vertex, three edges, two faces, and six half-edges. I reused the six existing half-edges where possible, created the six new ones, and then carefully set all next/twin/vertex/edge/face pointers for the four resulting triangles. I also marked the new vertex as isNew and flagged the two diagonal edges as new (while the two halves of the original edge stay isNew = false), which is exactly what Loop subdivision needs to distinguish the edges it should flip.

Part 6: Loop subdivision for mesh upsampling

Loop subdivision upsamples a triangle mesh by first subdividing each triangle into four, then smoothing the vertex positions. For a closed mesh, an edge splitting the shared edge (A,B) with opposite vertices C,D gets 3/8 (A+B) + 1/8 (C+D). An old vertex of degree n is updated to (1 - n u) position + u sum(neighbors), with u = 3/16 for n = 3 and u = 3/(8n) otherwise.

I follow the recommended three-step order: compute all new positions on the original coarse mesh; split every original edge and then flip the new diagonal edges that connect an old vertex to a new vertex; finally copy the computed positions into the vertices.
